## Delivered

- Extraction v1 prompts preserve operators, units, counting semantics, service vocabulary,
  scope and modality. Document text is treated as data rather than instructions.
- Extraction output is validated against the named source field. Invalid quotes and
  malformed numeric/qualitative constraints get one repair attempt, then fail closed.
- Semantic comparison receives scope/modality context and must cite an actual supplied
  decision. Missing/invented evidence cannot support either a conflict or a clean pass.
- Deterministic comparison checks decision quotes too, including cached constraints.
  Unknown service, partial environment coverage and uncertain conditions need review.
  Advisory/optional constraints do not become confirmed contradictions.
- Partial decision-extraction failures cannot create a clean pass. A failed comparison
  for one claim no longer discards supported conflicts on other claims.
- Golden data expanded from 15 to 30 scenarios (S16–S30), with one accepted cache-TTL
  recommendation. Existing S01–S15 data and expected outcomes are unchanged.
- `eval/score-scenario.ts` scores each extracted report against gold requirements,
  independently of its overall verdict. It detects missing/extra material claims,
  wrong operators/values/modality/scope, invalid evidence, per-claim verdict errors,
  duplicate IDs and incorrect coverage. Matching uses quotes/attributes rather than
  generated claim IDs, so reordering does not count as an extraction error. Equivalent
  numeric units are accepted. Decision quotes are checked against the reference library,
  not merely the report's own copy of the decision text.
- UI mock reports regenerated by `npm run fixtures` (33 fixtures). This is generated
  test data, not a change to Bảo's UI components or API client.

No shared schemas, adapters, handlers, Forge manifest, dependencies or infrastructure
were changed. `AssessInput.onError` is an optional engine-internal callback; existing
callers can keep their current interface. New tests are in `test/engine-safety.test.ts`,
`test/llm-extraction.test.ts`, `test/pipeline-failures.test.ts`, and
`test/evaluation-scoring.test.ts`.

Per-scenario results, coverage and error categories: `eval/offline-results.json`.
Generate this report with `node --import tsx eval/report-offline.ts`; it exits nonzero
on any expected outcome, claim reason, coverage or evidence mismatch.

For future extracted reports, the integration owner can call
`scoreScenario(goldScenario, analysisReport)` and collect the returned missing-claim,
field-error and outcome-error arrays. No handler or shared contract needs to change to
use this pure evaluator. This is prepared and tested offline; the existing Forge runner
has not been modified. Conditions and qualitative text are compared against strict
labels; legitimate paraphrases should be reviewed rather than treated as proven model
errors. This evaluator tests labelled extraction completeness, not whether arbitrary
real-world tickets have been exhaustively understood.

## Limits and next dependency

to exercise validation/repair and failure handling; they do **not** measure live model
accuracy or demonstrate resistance to prompt injection. Quotes present in the source
also do not prove the model extracted their meaning correctly.
